# Memory-heavy smoke tests -- the ones that must NOT run in parallel.
#
# scripts/run_qemu_smoke.sh runs the suite in two phases: everything not listed
# here at -n auto (one qemu per CPU), then everything listed here serially.
#
# Format: one glob per line, matched against the pytest node id (fnmatch, so
# `*` and `?` work); `#` starts a comment. A pattern with no wildcard is also
# tried as a plain substring, so a family can be named by the fragment its ids
# share. Patterns deliberately omit the `[-O0]`/`[-O2]` suffix so one line
# covers every optimisation level the suite is run at.
#
# Ranked by the guest kernel's peak process-pool usage, read from /proc/mempeak;
# reading that file clears it, so the harness brackets each test with two reads.
# Host RSS is the wrong instrument: qemu sits at ~72 MiB whatever the guest does,
# and the ordering it produces is inverted.
#
# To refresh:
#
#   YASOS_SMOKE_MEM_REPORT="$PWD/.cache/qemu_smoke_mem" \
#       ./scripts/run_qemu_smoke.sh --no-build --opt-levels -O2 tcc_suite_test.py
#   cat .cache/qemu_smoke_mem/*.tsv | sort -rn | head -20 \
#       | awk -F'\t' '{printf "%7.2f MiB  %s\n", $1/1048576, $3}'
#
# Report columns are `guest_peak_bytes<TAB>host_peak_kb<TAB>nodeid`.
#
# Measured over 4525 tests at -O2 (2026-08-11): median 0.50 MiB, p99 1.03 MiB,
# max 5.15 MiB. There is no real outlier, so this list is a margin rather than a
# rescue -- if a parallel run exhausts a machine, the cause is the constant
# ~72 MiB of qemu overhead times the worker count, and the lever is
# YASOS_SMOKE_XDIST=<n>, not this file.
#
# Threshold below: 2 MiB, 4x the median. Everything listed costs full serial
# wall time, so it is deliberately short.
