# yasos.zig — what changed between v0.0.8 and v0.1.0

**Video 2 of 2.** This covers the OS itself. The compiler submodule (`libs/tinycc`)
is a separate document — that half is big enough to need its own video.

Range: `v0.0.8` (`93f3422`) → `v0.1.0` (`98481c6`)
Wall time: **2025-12-04 → 2026-08-13** (~8 months)
10 commits on this repo, but two of them are large squashed PRs (#22, #23) and
one is a submodule bump that drags in six months of compiler work.

---

## The one-line version

> v0.0.8 was a single-core microcontroller OS with a shell, a filesystem and no
> synchronization to speak of. v0.1.0 boots a **second core**, has a real
> **lock hierarchy**, validates every pointer userspace hands it, has
> **`pipe(2)`**, runs its userland on **hardware floating point**, talks to SD
> cards over **4-bit SDIO through PIO**, and its full regression suite went from
> **54 minutes to 10 minutes 36 seconds** on the same board.

## Chapter 1 — SMP: the second core boots

This is the headline and the largest single body of work.
`docs/smp_plan.md` is 2,124 lines and is the design record.

**`CONFIG_PROCESS_SMP=y` is now the default on the Pico Plus 2**, and core 1
boots on both that board and QEMU MPS3-AN524, passes a two-core mutual-exclusion
test, and parks.

### What actually had to be built first

The bring-up is the visible part; the synchronization inventory is the project.
A whole new `source/kernel/sync/` module (~1,900 lines):

| File | What |
|---|---|
| `atomic.zig` | LDAEX/STLEX-backed atomics |
| `spinlock.zig` | spinlocks, IRQ state, reservation granule handling |
| `locks.zig` | **the ranked lock hierarchy** |
| `mutex.zig` | `RankedMutex` — sleeping mutex |
| `percpu.zig` | per-CPU state |
| `preempt.zig` | `preempt_disable()` / `preempt_enable()` |
| `refcount.zig` | atomic refcounts |
| `seqlock.zig` | `Seq64` — for the clock |
| `placement.zig` | coherency checks against the board memory map |

### The idea worth explaining on camera: ranked locks

Every lock in the kernel has a **rank**. Locks are acquired in increasing rank
and released in reverse, and `Ranked` enforces it **at runtime**:

```
bkl(5) → loader(8) → mount(10) → fs(20) → dev(30) → sdio → … → console (innermost)
```

Ranks run **mutexes before spinlocks**, so "never take a sleeping mutex while
holding a spinlock" is not a rule someone has to remember — it falls out of the
ordering. And `console` is the innermost leaf, so anything can log.

The numbers are sparse (5, 8, 10, 20, 30) so a new lock can be inserted without
renumbering. That's a small detail that shows the thing was designed rather than
grown.

### `block_context_switch` is gone

The old "just turn off preemption" hammer. **All 37 call sites were classified
and converted**, the alias deleted, and a **CI grep guards it** from coming back
(`scripts/verify_no_block_context_switch.sh`).

### The honest part

Two things measured on hardware that the plan document puts *at the top*, in a
callout, before any of the good news:

1. **`CONFIG_PROCESS_SMP=n` panics deterministically** — four sequential tcc
   compiles through `prun -j1`, the fourth dies with kernel heap exhaustion.
   Not bisected, so "the SMP work caused it" is unproven, but the single-core
   configuration is currently broken.
2. **SMP costs ~48% on the per-syscall console path** — the shell's per-character
   echo goes from **20.1 µs/char at SMP=n to 29.7 µs/char at SMP=y**. It doesn't
   show in the compile bucket because a compile is 77% XIP miss stalls and the
   syscall tax hides inside that. The echo path is nothing but syscalls, so it
   exposes it.

That kind of self-reporting is worth showing. It's more convincing than the
feature list.

### And one that closed a whole direction

Running two compiles concurrently on the two cores is **0.61x — a regression** —
and the cause is the **shared 16 KiB XIP cache**, not the scheduler and not
memory. The control arm settles it: a RAM-resident ALU loop gets **1.64x** from
the second core, while two tcc instances take 44% more cache misses for the same
work. Quartering the heap changes nothing, which rules out PSRAM spill.

So on-board test parallelism is closed. A *second board* is not — that adds a
second cache with the second core.

## Chapter 2 — The kernel stopped trusting userspace

**`source/kernel/uaccess.zig`** (249 lines) — validation of every pointer
userspace hands the kernel.

The reasoning in the file header is the best 30 seconds of the video:

> Syscall handlers run privileged, so an unchecked pointer is an arbitrary
> read/write primitive for any process. **The MPU is no defence**: PRIVDEFENA
> plus the background map means it only ever restricted *unprivileged* access.

A valid user pointer may point at user RAM (process SRAM and PSRAM) for a write,
and additionally at the read-only executable image for a read — because the
loader **borrows `.rodata` from XIP rather than copying it**, so `open("/bin/ls")`
legitimately passes a flash pointer. Kernel RAM, the `/tmp` arena, MMIO and the
PPB are all excluded — MMIO because a DMA engine programmed through it can write
kernel RAM.

Stated limit, in the file itself: it is **region-granular, not per-process**. It
stops a process reaching kernel memory; it does not stop process A reaching
process B's pages. That needs the page pool's per-pid map.

Alongside it: **MPU support for ARMv8-M (PMSAv8) and ARMv6-M**
(`source/arch/armv8-m/mpu.zig`, `source/arch/armv6-m/mpu.zig`) protecting the
kernel heap and kernel stack from unprivileged processes, and a syscall layer
that now distinguishes trusted from untrusted callers and checks string vectors,
ioctl arguments and dirent buffers.

## Chapter 3 — `pipe(2)`

`source/kernel/fs/pipe.zig`, 508 lines. Two ends, presented as ordinary `IFile`s
— which is the whole trick:

> so dup2/close/redirects and the fd table copy a `vfork` makes all work with no
> special cases

The ends share a ring buffer plus the count of ends open for reading and
writing, which is what makes **EOF on a readerless write and a writerless read
decidable**.

Blocking is the sleeping mutex's yield loop — block under the guard, trigger
PendSV until woken — not a spin, because the process on the other end only runs
if this one gives up the core. Marking the waiter blocked *under the lock* is
what stops the wake-up being lost.

New syscalls in this release: **`pipe`**, `ftruncate`, `mremap`, `prlimit`,
`klog_ctl`, `perf_dump`.

## Chapter 4 — Memory

- **`process_memory_pool.zig`** 843 lines of change, **`process_page_allocator.zig`**
  282 — cheap process-pool allocation was one of the measured wins
- **Hybrid `/tmp`** (`tmp_memory_pool.zig`, `tmp_page_allocator.zig`,
  `ramfs_tier.zig`) — small files (≤64 KB by default) RAM-backed with a total
  arena budget, larger files spill to SD. Motivated by hard experience: an
  unbounded SRAM RamFs starved code and heap and was a net loss.
- **Kernel heap locking** (`kheap_lock.zig`), `malloc.zig` reworked
- New **procfs instrumentation files**: `/proc/cpus`, `/proc/maps`,
  `/proc/mempeak`, `/proc/leakdetect`, `/proc/uartstat`, `/proc/xipstat`

That last one matters more than it sounds: `xipstat_file.zig` (276 lines)
exposes XIP cache accesses and misses to userspace, and it is what made the
"the compile is memory-bound, not core-bound" conclusion measurable rather than
speculative.

## Chapter 5 — Storage: SDIO over PIO

At v0.0.8 the SD card was SPI. v0.1.0 adds **4-bit SDIO driven by the RP2350's
PIO** — `sdio_rp2350.c` (1,445 lines), `sdio_rp2350.pio` (365 lines), plus the
Zig wrapper `mmc_sdio.zig` (663 lines). Selected by
`CONFIG_MMC_BUS_MODE_SDIO` (default on the Pico Plus 2; MSPC v2 stays on SPI).

Plus:
- **FatFs line cache** (`CONFIG_FATFS_CACHE_LINE_SECTORS`, `CONFIG_FATFS_CACHE_LINES`)
- **CMD25 multi-block writes** — the measured effect is the best table in the repo:

| `write()` size | before | after |
|---|---|---|
| 512 B | 373 KiB/s | 376 KiB/s (unchanged — single sectors keep CMD24) |
| 4 KiB | 406 KiB/s | **2,139 KiB/s** |
| 32 KiB | 412 KiB/s | **3,514 KiB/s** |

Reads and scattered single-sector writes: unchanged, as they should be. That
last row is what makes a measurement trustworthy.

- **`yasdisk`** — a new on-device partitioning tool with a TUI, MBR read/write,
  its own C unit tests (acutest) and a pytest integration suite
- **`sdbench`** — an on-device SD throughput benchmark
- `scripts/fatimg/` — a host-side FAT image builder for the QEMU smoke disk

## Chapter 6 — Performance: 54 minutes → 10:36

`docs/remote_smoke_speedup_plan.md` (2,181 lines) is the whole story, and it is
structured as measure → attack → re-measure. Worth showing the document itself.

### The starting split (2026-07-30 baseline, 4,531 tests, one RP2350)

| Bucket | Share |
|---|---|
| On-target tcc compile | 66% |
| Harness / serial overhead | 32% |
| On-target test execution | 1.3% |

The suspicion going in was tcc performance and PSRAM. The measurement said the
time split three ways, so all three got attacked — measurement phase **first**,
explicitly because *"host profiling has misled before (5% host vs 44% target for
vrp)"*.

### The ladder

| Run | Wall | What landed |
|---|---|---|
| 2026-07-30 | **54:20** | baseline |
| 2026-08-03 | 31:44 | harness batching, hybrid /tmp, CMD25 writes |
| 2026-08-04 | 25:09 → 22:57 → 20:47 → 20:44 | loader fixes, the init floor, the tail round |
| 2026-08-05 | 17:23 | -O0 codegen dry-walk |
| 2026-08-06 | **10:36** | the transaction round |

**−80.5% against baseline**, same pass set throughout.

### Three findings worth telling as stories

**1. The compile is memory-bound, and it is not close.** A clock A/B: 618 MHz vs
532 MHz changed median compile wall by **+0.96%** — i.e. nothing. Per compile:
38.3 M XIP accesses, ~495 k misses, 98.71% hit rate. Of a 167 ms compile,
**35% is core execution and 65% is stalled on XIP cache misses.**

**2. The flash was being read wrong.** The chip-select deselect time had been
taken from the datasheet's *erase/program* row instead of its *read* row, and
every XIP miss was clocking out an opcode the part did not need. Fixing what a
miss *costs* (rather than how many there are) took the compile bucket 557.6 s →
489.3 s. Getting there required root-causing a **PIO autopull race** that had
been breaking SD bring-up for two rounds under the description "any codegen
change breaks the card."

**3. The 41 ms "init" was builtin alias declarations.** The per-compile floor was
85.8 ms. Most of the tcc-init half turned out to be the builtin alias
declarations thrashing XIP; building them programmatically took the floor to
**25.8 ms**.

### Also in this chapter

- **Overclocking** — `overclock.c` (455 lines), RAM-resident because it touches
  flash-mapped VREG and does an atomic PLL + QMI switch. Board default is
  **532 MHz**; 618 MHz is this board's measured stable max (and single runs lie —
  the failures are ~80% intermittent).
- **XIP and PSRAM tuning exposed as Kconfig** — XIP max frequency, select/deselect
  timings, continuous read; PSRAM frequency, CE timings, and a
  frequency-dependent RX delay
- **Kernel profiling** — `perf_profile.zig` (629 lines), `sys_perf_dump`,
  `tests/smoke/kernel_profile.py`, `syscall_profile_test.py`, `io_profile_test.py`
- **`syscallbench`** — a userland syscall round-trip benchmark

## Chapter 7 — Userspace runs on the FPU

`CONFIG_BUILD_USERSPACE_HARDWARE_FP` — the whole rootfs (every library, every
app, and the on-device C compiler) built against the CPU's floating point
hardware.

The design decision is the interesting bit. It is compiled **into the toolchain**
(`-DCONFIG_TCC_DEFAULT_FPU=…`) rather than passed per target, because:

> only about half the Makefiles under `libs/` and `apps/` thread `ROOTFS_OPT_CFLAGS`
> into their `CFLAGS`, none thread it into `LDFLAGS`, and the link step is what
> selects the matching `__aeabi_*` runtime.

One knob in the compiler reaches all libraries and apps including the ones with
hardcoded flags (`yasos_curses`, `textvaders`, `yasvi`, `zork`, toybox), tcc's own
native bootstrap, every link, **and programs compiled later on the device** —
which then match the libraries they link against.

Default on the Pico Plus 2: `CONFIG_BUILD_USERSPACE_FP_MFPU="rp2350"` — the DCP
coprocessor path.

Supporting work: DCP save/restore across context switch, an FP-mode rebuild
stamp so a mode change forces a clean rootfs, and `libs/libm` substantially
expanded (788 lines of change plus a new 263-line test suite).

## Chapter 8 — The loader (yasld)

- **`dynamic_loader/elftoyaff/` deleted** — the Python ELF→YAFF converter
  (`mkimage.py` alone was 971 lines) plus its CMake toolchains, ~3,000 lines
  gone. It was the legacy GCC path; tcc emits YAFF directly now, so the
  conversion step stopped existing.
- **Symbol hash table** attached to modules — lookup instead of linear scan
- **Per-phase load accounting** (`load_profile.zig`) — so "the spawn is slow" can
  be attributed
- **Atomic refcounts** on modules (`refcount.zig`)
- The **indirect-call thunk** now tail-jumps instead of pushing before `blx`.
  Worth a sentence: the old thunk displaced stack arguments 5 and up.
- `scripts/yasld_gdb.py` (235 lines) — GDB helper that maps loaded modules to ELFs

## Chapter 9 — Two new targets, both in QEMU

**`qemu_mps2_an505`** and **`qemu_mps3_an524`** — full HAL ports: startup, linker
script, UART, timers, flash, external memory, CPU. ~2,400 lines each.

This is what makes the CI story possible: a QEMU smoke run
(`scripts/run_qemu_smoke.sh`, 384 lines) that needs no board. It is also the
single-core-vs-SMP classifier — MPS3-AN524 is where core 1 was brought up first.

Caveat worth stating: the QEMU smoke never exercises the exit/shutdown path, and
a QEMU run costs two clean rootfs rebuilds.

## Chapter 10 — Test and tooling infrastructure

This is ~13,500 lines and half the diff by file count.

**`scripts/remote_smoke_tui.py` — 3,532 lines.** Build locally, `scp` the
artifacts, flash over `ssh`, run the suite on the machine the board is attached
to. Caches its config, so `--run-cached` is a one-liner. Numbered run directories
(`workdir/logs/1`, `logs/2`, …, `logs/latest`) each with a `run_info.txt`
recording kernel/rootfs hashes, opt levels, cflags, git revision and exit status
— **so an A/B is comparing two directory numbers**, which is exactly what a
kernel or compiler change needs.

**The `-O` matrix.** Every smoke runner defaults to the full **`-O0 -O1 -O2`**
matrix — the tests2 suite, ir_tests and GCC torture alike, run once per level.

**ZMODEM file transfer** — `apps/rzsz/zmodem/zmodem.c` (635 lines) plus CRC32,
and a host-side `tests/smoke/framework/file_transfer.py` (807 lines). This is how
test corpora get onto the device without reflashing.

**`prun`** — runs a batch of shell commands on the device concurrently, from a
single console round trip. The header comment is a good "embedded is different"
moment:

- `cmd &` doesn't work — toybox takes the `fork()` path and this kernel has only
  `vfork()`
- never pass `environ` to `exec` — the kernel builds argv/environ on the kernel
  heap, and uaccess refuses those addresses to userspace
- jobs are exec'd directly, not through `sh -c`, because spawning `/bin/sh` from
  a vforked child HardFaults this kernel

**Timing and profiling instruments** — `timing.py` (846), `profiling.py` (425),
`measure_test.py` (1,042), `prun_scaling_test.py` (846), plus host-side unit
tests *for the harness itself* (`tests/test_smoke_timing.py`,
`tests/test_tcc_suite_harness.py`, 873 lines).

**HardFault triage** — `scripts/collect_decode_bundle.sh` packages firmware +
rootfs + symbol ELFs so a fault address can be `addr2line`'d from CI artifacts.
The fault handler itself dumps module maps.

New smoke suites: `smp_test.py`, `vfork_test.py`, `pipe_test.py`, `vi_test.py`,
`sd_write_perf_test.py`, `sd_bringup_soak_test.py`, `yaff_arch_test.py`,
`io_profile_test.py`, `syscall_profile_test.py`, `prun_scaling_test.py`.

## What is scaffolded but not shipped

Say this, don't skip it — it is more credible than pretending otherwise:

- **Virtual terminals.** `docs/virtual_terminals.md` (412 lines) is a complete
  design — `/dev/tty0`-`/dev/ttyN`, a UART mux, per-VT process groups, `chvt`.
  `vt_driver.zig` / `vt_file.zig` exist. But `initialize_virtual_terminals()` in
  `source/main.zig` is **commented out**. The design landed; the feature has not.
- **PTY / yamux** — `docs/pty_and_yamux_plan.md`, 606 lines, plan only.
- **SMP phase 6+** — the doorbell IPI and two diagnostic globals. Core 1 boots
  and parks; it does not yet schedule work.
- **`CONFIG_PROCESS_SMP=n`** — currently broken (see Chapter 1).

### Demos that will land

1. **`cat /proc/cpus`** on the board. Two cores. That's the whole video in one
   command.
2. **`cat /proc/xipstat`** during a compile — watch the miss counter. Then the
   clock A/B: it barely moves.
3. **`ls | grep x`** — a pipeline running on a Cortex-M33.
4. **`yasdisk`** — a partitioning TUI on a microcontroller.
5. **`prun -j4 batch.txt`** — four compiles at once, then show the 0.61x result
   and explain why the answer was "no".
6. The remote smoke TUI running a full suite, with the timing report at the end.
7. **Compile a C file on the device** with `/usr/bin/tcc` and run it. That closes
   the loop with video 1.

### Things to say that are true and unusual

- The lock hierarchy is checked at runtime, and its *ordering* is the contract —
  the numbers are sparse on purpose.
- The kernel does not trust its own MPU for this; PRIVDEFENA means the MPU never
  restricted privileged access, so pointer validation is explicit code.
- A 6.7x regression-suite speedup came almost entirely from measuring rather than
  guessing — including a bug that was a *datasheet row* being read wrong.
- Two cores made concurrent compiles **slower**, and the project published that
  and closed the direction.
- Userland floating point is configured in the compiler, not the Makefiles,
  because half the Makefiles don't cooperate.
